# 输出页原型草图 — ticket 06

> 定稿不落库，结果用完即弃。用户在 WebUI 看 N 份候选 + 审查意见，选一份/编辑后定稿。
> 候选份数 = 生成风格槽位数（见 issues/07），每份对应一个用户配置的风格 prompt+temperature。

## 页面布局

```
┌─────────────────────────────────────────────────────────┐
│  生成结果                              [重新审查] [改输入] │
├─────────────────────────────────────────────────────────┤
│                                                         │
│  ┌─ 审查意见 ──────────────────────────────────────┐    │
│  │ 综合评价：三份候选都抓住了卖点，但 CTA 偏弱。    │    │
│  │ 候选0：开头钩子强，结尾仓促。                    │    │
│  │ 候选1：结构最完整，CTA 可用。                    │    │
│  │ 候选2：语气偏正式，与品牌 tone 不符。            │    │
│  │ 建议：以候选1为基底，补强 CTA。                  │    │
│  └──────────────────────────────────────────────────┘    │
│                                                         │
│  候选 [○ 0] [● 1] [○ 2]          ← 选中态：可编辑/定稿   │
│  ┌──────────────────────────────────────────────┐      │
│  │ <选中候选的可编辑文本>                         │      │
│  │                                              │      │
│  │  ← 直接在框内改字，非技术用户也能微调          │      │
│  └──────────────────────────────────────────────┘      │
│                                                         │
│                              [复制] [定稿]              │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

## 交互流（对应 ticket 四问）

1. **页面结构**：
   - 顶部：审查意见块（综合意见 + 每份候选简评，来自 `/generate` 的 `done` 事件 `review` 字段）。
   - 中部：候选选择器（标签页/单选卡片，0/1/2），切换查看每份。
   - 下方：选中候选的**可编辑文本框**。
   - 右上：`[重新审查]`（调 `/re-review`，复用当前候选重跑审查）、`[改输入]`（回上页改输入重走整条流水线）。
   - 右下：`[复制]`（复制当前文本框内容）、`[定稿]`（标记完成）。

2. **定稿交互（不落库）**：
   - `[定稿]` 仅前端状态切换 → 显示「✓ 已定稿」反馈，内容不写 DB。
   - `[复制]` 把文本框内容（可能已编辑）复制到剪贴板，用户自行粘贴到外部。

3. **编辑再定稿**：选中的候选直接在文本框内可改，改完 `[定稿]`。无需「保存」——编辑即内容，定稿即确认。非技术用户改个别字零门槛。

4. **重新审查入口**：右上 `[重新审查]`，调 `/re-review` 传当前 drafts + input_vars，返回新 review 替换意见块。候选项不变（见 issues/03）。

## 状态机

```
loading(generating) → reviewing → done(drafts+review)
                                   ├─ 选中候选 → 编辑 → 定稿
                                   └─ [重新审查] → reviewing → done
```

## 与后端契约

- `/generate` SSE `done` 事件 → `{drafts: string[], review: string}`
- `/re-review` → `{drafts, review}`（drafts 原样回传，review 更新）
- 前端本地态：`selectedIdx`、`editedText`、`finalized: bool`（刷新即丢，不落库）

## react 点

- 候选用「单选卡片切换 + 一个文本框」还是「并排三列各自文本框」？前者省空间、聚焦编辑；后者便于横向对比。草图选了前者，因「编辑再定稿」是主交互。
- 「改输入」是否需要？还是用户直接回上页即可——若回上页能保留输入态，这按钮可砍。
