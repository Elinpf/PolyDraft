# Design: 选项维度配置 + 生成页下拉化

## Context

产品已跑通 MVP，进入打磨阶段。产品同学习惯「选维度 → 出文案」而非自由填空。现有生成页是输入变量表单（topic/brand/tone 现填），与产品心智不匹配。本 change 引入可配置的选项维度，把生成页改为下拉单选，并让文案类型等维度的选项能带 prompt 约束片段注入。选项由产品在前台 WebUI 自助维护。

## Goals / Non-Goals

**Goals**
- 选项维度可配置（前台 CRUD），区分纯值维度与带 prompt 片段维度。
- 生成页改为下拉单选，按维度动态渲染。
- 生成时所选维度的值与 prompt 片段并入变量上下文渲染。
- 默认 seed 产品系列/产品段位/文案类型三个维度及默认选项。

**Non-Goals**
- 产品知识按系列联动注入（Change B）——本 change 产品知识仍是全局变量，选产品系列只填值，不联动知识。
- 审查流程改造（Change C）。
- 文案通俗化/技术词替换（Change D）——本 change 暂用现有术语。
- temperature 对产品可见性调整（Change D）。

## Decisions

### 1. 选项维度数据模型
```
option_dimensions 表:
  id, name (维度名，如「产品系列」), kind ('value' | 'prompt')  -- 纯值 vs 带prompt片段

option_choices 表:
  id, dimension_id, label (显示文本，如「朋友圈」), value (注入值，如「朋友圈」或标识),
  prompt_fragment (仅 kind=prompt 维度用，纯值维度为空)
```
维度名与选项 label/value 的语言由产品自定。生成时维度名作为变量 key（如 `{产品系列}`）。

### 2. 变量注入机制
生成请求携带用户所选的「维度→选项」映射。后端把：
- 纯值维度：`{维度名}` = 选项 value
- 带 prompt 维度：`{维度名约束}` 或约定 key = 该选项的 prompt_fragment

并入 merge_variables 的输入，与全局变量、输入变量合并注入。

**注入到哪里（system vs user）**：维度的值与 prompt 片段都并入统一变量上下文，由 prompt 里 `{var}` 写在哪决定进哪个 message（复用现有机制，不特殊处理）。文案类型约束这类「本次任务约束」，默认建议写在槽位 prompt 里，但产品可自由决定。

### 3. 生成页 UI
- 进入生成页：拉取已配置的维度列表 → 每个维度渲染一个下拉框。
- 顶部仍保留 provider 选择与「生成」按钮。
- 不再显示自由填空的输入变量表单（输入变量维度仍可在后台用，但生成页主交互是下拉）。

### 4. 选项维度管理页
新增 tab「选项维度」：列出维度，每个维度下管理选项。支持增删改维度与选项。

## Risks / Trade-offs

- [维度名作为变量 key，中文 key 在 `{var}` 渲染时需兼容] → 现有 `_render` 用 `format_map`，中文 key 可行，但需测试。
- [选项维度与现有输入变量/全局变量的冲突优先级] → 简单规则：输入变量 > 选项维度 > 全局变量（或同等），需明确并在文档说明。
- [前台配置可能产生重复/冲突的维度名] → 后端校验维度名唯一。

## Open Questions

- 变量注入的 key 命名约定：纯值维度用 `{维度名}`，带 prompt 维度用什么 key（`{维度名约束}`？还是维度名加固定后缀）？开实现时定。
- 是否允许同一维度被多次选（多选）？本 change 仅单选。
