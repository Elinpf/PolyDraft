## Why

当前生成页采用「输入变量表单自由填空」的形态，偏技术化，与产品同学「选维度 → 组合 → 出文案」的心智模型不匹配。产品部门需要通过下拉单选（产品系列、文案类型、产品段位）驱动生成，且每个选项可由产品自己在前台维护、文案类型选项背后带对应的 prompt 约束片段。本 change 将生成入口从自由填空改为可配置的下拉选项式，让非技术用户用着自然。

## What Changes

- 新增「选项维度」概念：一组可配置的枚举维度（如产品系列 A/B/C/D、产品段位 1/2/3、文案类型 朋友圈/1v1/社群/小红书），由产品在前台 WebUI 维护。
- 每个选项维度区分类型：
  - **纯值维度**（产品系列、产品段位）：选项只是值，选中后把值填进对应变量。
  - **带 prompt 片段维度**（文案类型）：每个选项除值外还带一段 prompt 约束（如「朋友圈：不超过7行，每行…」），选中后把该段注入 prompt。
- 生成页 UI 重做：从输入变量表单改为下拉单选式，按配置的维度动态渲染下拉框。
- 生成时：所选维度的值与 prompt 片段作为变量注入 system/槽位 prompt 渲染。
- 新增「选项维度」管理页（前台 CRUD），产品可自助增删改维度与选项。
- 与「产品知识联动」相关的部分（选产品系列注入对应知识）不在本 change，归 Change B。

## Capabilities

### New Capabilities
- `option-dimensions`: 可配置的选项维度——前台维护的枚举维度与选项，区分纯值维度与带 prompt 片段维度，供生成页下拉渲染与生成时变量注入。

### Modified Capabilities
- `generation-ui`: 生成页从自由填空表单改为下拉单选式，按选项维度动态渲染；本次任务的维度选择结果驱动生成。
- `variable-system`: 变量注入新增「选项维度」来源——所选维度的值与 prompt 片段作为变量参与 merge 渲染。

## Impact

- 新增后端 `option_dimensions` 表 + 存取函数 + 路由（CRUD）。
- 改 `backend/pipeline.py`：生成前把所选维度值/prompt 片段并入变量上下文。
- 改前端生成页：从输入变量表单改为下拉单选（动态渲染）。
- 新增前端「选项维度」管理页。
- 不动产品知识（仍在 variables，Change B 独立）。
- 不动审查流程（Change C）。
- 文案通俗化（Change D）不在本 change，本 change 暂用现有术语。
