## Why

当前审查是「全部候选拼一起做一次综合审查、最后选一份定稿」。但产品部门的工作流是：每份风格候选都要独立审核、独立保留（因为风格不同没有「最好」），未过的修改后重新审核，最终每份都要定稿。审查内容也需要结构化为三个维度：正向亲和、反向亲和、产品知识准确性，并给综合打分供人判断。本 change 改造审查与定稿流程以匹配产品真实工作流。

## What Changes

- 审查从「一次综合」改为「每份候选独立审核」：N 份候选 → N 次审查调用，各自产出意见。
- 审查产出结构化：综合打分（分数）+ 三维度意见（正向亲和、反向亲和、产品知识准确性）。LLM 给评分与意见，是否通过由人判断。
- 每份候选维护独立的审核状态（待审/已审）、审核意见、定稿状态。
- `/re-review` 改为支持单份重审（接收某一份候选，重审这一份）。
- 定稿从「选一份」改为「每份各自定稿、全部保留」：一次生成可产生 N 条定稿记录。
- `finalized` 表结构调整为按候选粒度记录（含候选来源、审核意见、定稿文本）。

## Capabilities

### New Capabilities
- `per-candidate-review`: 每份候选独立审核——三维度意见（正向亲和/反向亲和/产品知识准确性）+ 综合打分，LLM 产出供人判断；支持单份重审。

### Modified Capabilities
- `review`: 审查从一次综合改为 N 次独立；审查 prompt 调整为要求三维度结构化输出 + 打分；`{candidates}` 拼接方式不再适用（改为单份输入）。
- `generation-ui`: 输出页每份候选展示独立审核状态/意见/打分；每份可独立定稿；单份重审入口。
- `generation-api`: 流水线事件结构调整——审查阶段对每份候选产出独立结果；`/re-review` 支持单份。

## Impact

- 改 `backend/pipeline.py`：审查循环 N 次，每份独立调用，产出结构化意见。
- 改审查 prompt：要求输出「综合打分 + 正向亲和 + 反向亲和 + 产品知识准确性」三维度。
- 改 `backend/app.py`：`/re-review` 改为单份；SSE done 事件结构变化（每份带审核结果）。
- 改 `finalized` 表：增加候选来源、审核意见、打分字段；一次生成 N 条。
- 改前端输出页：每份候选卡片含审核状态/意见/打分/定稿按钮。
- 不动选项维度（Change A）、产品知识（Change B）。
